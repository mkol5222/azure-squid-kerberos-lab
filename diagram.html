Kerberos SPNEGO auth flow (client → proxy)

1
Client requests a service ticket for HTTP/proxy.lab.contoso.local from the DC's KDC (port 88). Requires proxy addressed by FQDN, not IP.
2
DC/KDC issues the ticket using the AES256 key shared with the squid-http computer object created by msktutil.
3
Client presents the ticket to Squid via an HTTP Negotiate header on port 3128.
4
Squid validates it against its keytab using negotiate_kerberos_auth — no password prompt, no credential ever leaves the client.
5
Request proxied onward to the internet; user only sees a normal page load.

Micro-segmentation

Explicit Deny-VnetInBound-Override (4096) overrides Azure's default allow-all-in-VNet rule per NSG.

AES-only Kerberos

aes256/128-cts-hmac-sha1-96 only — RC4/DES from the original wiki example are disallowed.

No hardcoded secrets

Admin password comes only from TF_VAR_admin_password at apply time — never written to a script file.
